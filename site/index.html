A blazingly fast, drop-in companion to SwiftPM

swx resolves, builds and runs Swift packages, and writes SwiftPM's own files byte for byte. It is written in Swift, reads Package.swift as it is, and works alongside swift and Xcode, so there is nothing to migrate.

curl -fsSL https://swx.quadratic.xyz/install.sh | sh

macOS 13+ (universal) and Linux (static, x86_64 and aarch64). Other ways to install.

Key features

  • Fast: cold resolves about 4× faster than SwiftPM, and a no-op in 20 ms.
  • Drop-in: the same Package.resolved, .build/checkouts and workspace-state.json as SwiftPM.
  • Familiar: SwiftPM's commands and flags; anything swx doesn't handle is forwarded to swift package.
  • Xcode-aware: prepares SourcePackages so xcodebuild builds offline.
  • Apple platforms: build, run and test on iOS, watchOS, tvOS and visionOS simulators and devices.
  • One-step edits: swx add swift-argument-parser finds the package, picks its newest release and library, edits Package.swift and resolves; remove and upgrade too.
  • Inspection: why, outdated, audit for known vulnerabilities, licenses, and undeclared imports, with a policy file for CI.
  • Fast CI: a GitHub Action, selective testing, and a remote cache on S3, HTTP or a directory that restores checkouts without git and build outputs without recompiling.
  • Dependency graphs: swx graph as a tree, Graphviz, Mermaid or JSON, with each edge's conditions.
  • Toolchains: installs swift.org releases and snapshots, and honours .swift-version.
  • Tools and scripts: runs package executables like uvx, and single-file scripts with dependencies.
  • Registries: SE-0292 registries with authentication, SE-0391 signatures and SwiftPM's trust store.

Philosophy

The goal of swx is to make working with Swift packages fast, without ever being distinguishable from SwiftPM in the files it leaves behind. To that end, swx:

  • Writes exactly what SwiftPM and Xcode would, and proves it with differential checks in CI.
  • Does no work it can avoid: an unchanged lockfile is a no-op, and missing checkouts are restored without solving.
  • Keeps the network and every core busy, pipelining tag listing, manifest fetches and checkouts with resolution.
  • Never guesses: a manifest it can't prove harmless is evaluated by the compiler, as SwiftPM does.
  • Leaves building to the build systems: SwiftPM for the host, xcodebuild for Apple platforms.

swx is written in Swift. It reads manifests with SwiftParser, adapts parts of SwiftPM itself, and keeps one global, content-addressed store whose checkouts are copy-on-write clones, so a dependency is fetched once per machine instead of once per project.

Example

swx package resolve        # same Package.resolved as `swift package resolve`
swx build -c release       # resolves, then SwiftPM builds with resolution disabled
swx test
swift build                # still works: everything is already resolved
swx devices                                # simulators and paired devices
swx run  --platform ios HelloApp           # build, install, launch, stream console
swx test --platform watchos                # package tests on a watchOS simulator
swx xcode resolve --source-packages SourcePackages
xcodebuild -clonedSourcePackagesDirPath SourcePackages \
           -disableAutomaticPackageResolution -onlyUsePackageVersionsFromResolvedFile …
#!/usr/bin/env -S swx run
// swx-dependencies:
// .package(url: "https://github.com/apple/swift-argument-parser", from: "1.3.0")

import ArgumentParser

Vapor + Fluent (32 packages), Apple Silicon, Swift 6.4. Both tools start from their own empty caches, and every run produced byte-identical files. The cold resolve depends most on the network, so it is the median of three runs. Scripts/benchmark.py reproduces the runs.
